# v0.7.0 Implementation Plan

## Phase 1: Core Features

### 1.1 Context Attachments
- Add `context` table to SQLite (collection, path, summary, created_at)
- Add CRUD methods to Storage: `add_context`, `get_context`, `list_contexts`, `remove_context`
- Add MCP tools: `kb_context_add`, `kb_context_list`, `kb_context_rm`
- Add CLI commands: `docs-haven context add/list/rm`

### 1.2 LLM Argument Aliasing
- Create `alias.py` with common alias mappings
- Intercept at MCP transport level before tool execution
- Log aliased calls for debugging

### 1.3 Export/Import CLI
- `docs-haven export --format json/csv > backup.json`
- `docs-haven import backup.json`
- `docs-haven export --collection fastapi --format markdown`

## Phase 2: Search Improvements

### 2.1 Auto Chunking Strategy
- Detect file type (code vs markdown)
- Use AST-based chunking for Python/JS files
- Keep regex chunking for markdown/text

### 2.2 Full Hybrid Search
- Blend BM25 + vector + LIKE scores
- Configurable weights per strategy
- Auto-detect best strategy

### 2.3 Incremental Embedding
- Track document hashes in DB
- On update, only re-embed changed chunks
- Background worker for bulk re-embedding

## Phase 3: CLI Improvements

### 3.1 Collection Rename
- `docs-haven collection rename old_name new_name`

### 3.2 Multiple Output Formats
- `--format json/csv/md/xml` for all CLI commands
- Structured output for integration

### 3.3 Conflict Resolution UI
- `docs-haven conflicts resolve`
- Show diff between conflicting docs
- Suggest merge strategies

## Phase 4: Coverage & E2E

### 4.1 Unit Tests
- Test all new methods
- Test edge cases

### 4.2 E2E Tests
- Full workflow tests
- Import/export round-trip
- Conflict resolution flow

### 4.3 Coverage Target
- 84% → 90%+
